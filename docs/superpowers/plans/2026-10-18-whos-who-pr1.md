# Who's who (PR 1 of 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A spoiler-free who's who page that grows with what the reader has read. This PR has the data format, the
pipeline validation, the review aid, the page reached from the reader, and a starter cast (Jonathan, Mina, Lucy,
Arthur, Seward, Quincey).

**Architecture:**
- **Pipeline.** Hand-written profiles live in `data/whos_who.yaml`. The pipeline validates every tie to an entry id
  and emits `data/out/whos_who.json`, sorted into story order. The app bundles it next to `entries.json`.
- **App.** It decodes the file into `Story.whosWho`. A pure function, `visibleWhosWho`, turns it plus the reader's
  progress into what may be shown. A new screen, `WhosWhoScreen`, shows that, opened from a reader top-bar button.

**Tech Stack:** Python 3.12 + PyYAML + pytest (pipeline). Kotlin, Jetpack Compose Material3, kotlinx.serialization,
DataStore, Robolectric (app).

**Spec:** `docs/superpowers/specs/2026-10-18-whos-who-design.md`

## Global Constraints

- No new dependencies, in the app or the pipeline. No new Android permissions. The privacy policy is unchanged.
- Exact copy:
  - The reader button and the page title are `Who's who`.
  - The empty page says `People appear here as you meet them in the story.`
  - The unseen-line mark is `new`.
- **Read** means `EntryProgress.readAtMillis != null`. Every line, name, group name and group move checks **only its
  own** entry (`from`).
- The name and group shown are the latest tie whose entry is read, falling back to the first tie.
- A person shows only when at least one of their lines shows. A group shows only when at least one of its people
  shows.
- `new` means: `whosWhoSeenAt != null && readAtMillis > whosWhoSeenAt`. The first visit marks nothing.
- `openOn` matches the entry's `author` only. It never reveals a person who isn't otherwise shown.
- Pipeline checks: `cd data && python -m pytest`, `ruff check .`, `python -m pipeline build --strict`.
- App checks: `cd app && ./gradlew :app:testDebugUnitTest :app:lintDebug` (JAVA_HOME = Android Studio's `jbr`).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never `git add data` wholesale:
  `data/out/calendar.html` is untracked and must stay out.

## Review Focus

1. **Open on someone not yet shown.** Free mode: the reader taps Who's who before `markRead` lands, or on an entry
   whose author has no line yet. The page opens at the top and nothing hidden appears. Test in Task 4.
2. **An author with no profile** (newspaper, firm, Stoker). The page opens at the top without crashing. Test in
   Task 4.
3. **Rotation mid-visit.** `new` marks and unfolded profiles stay as they were. The seen-at write mustn't clear the
   marks the reader is looking at. Test in Task 4.
4. **A build with no `whos_who.json` in assets**, or a dataset without the YAML. This gives an empty page, not a
   crash or a failed build. Tests in Tasks 1 and 3.
5. **An entry id that disappears** after a dataset change. The build fails and names the person and the id. Test in
   Task 1.

### Task 1: Pipeline: load, validate and emit the who's who

**Files:**
- Create: `data/pipeline/whos_who.py`
- Modify: `data/pipeline/cli.py` (`PipelineRun`, `run_pipeline`, `_build`)
- Test: `data/tests/test_whos_who.py`, `data/tests/test_cli.py`

**Interfaces:**
- Produces:
  - `Tie(source: str, value: str)`: frozen dataclass. `source` is an entry id, and `value` is text or a group id.
  - `Group(id: str, names: tuple[Tie, ...])`
  - `Person(id: str, groups: tuple[Tie, ...], names: tuple[Tie, ...], lines: tuple[Tie, ...])`
  - `WhosWho(groups: tuple[Group, ...], people: tuple[Person, ...])`. Groups are kept in file order.
  - `load_whos_who(yaml_text: str) -> WhosWho`. Empty or missing text gives an empty `WhosWho`.
  - `whos_who_problems(ww: WhosWho, entries: list[Entry]) -> list[Problem]`. Every problem is `level="error"`, with
    `entry_id` set to the person or group id.
  - `whos_who_json(ww: WhosWho, entries: list[Entry]) -> str`
  - `PipelineRun.whos_who: WhosWho`

YAML shape: top-level `groups:` (an ordered map of id → `names:` list) and `people:` (map of id → `group:`, `names:`,
`lines:` lists). Each list item is `{from: <entry id>, text: <str>}`, or `{from, id}` for `group:`.

JSON shape: `{"groups": [{"id", "names": [{"from", "text"}]}], "people": [{"id", "groups": [{"from", "id"}],
"names": [...], "lines": [...]}]}`.
- Every tie list is sorted by the `order` of its entry.
- Groups stay in file order.
- People are sorted by the `order` of their earliest line, then by id.
- Use the existing `_dump` style: `sort_keys`, indent 2, a trailing newline. Reuse it from `emit.py`.

The spec also asks that "a new id matching a `characters.yaml` id meant for someone else" fail the build. A program
can't tell who an id is meant for. So that rule is checked by the owner on the review page (Task 2), not by
validation.

**Interfaces:**
- Consumes: Task 3's `WhosWho`, `Story.whosWho`, `Story.entry(id)`, `Story.characters`; `EntryProgress.readAtMillis`.
- Produces:
  - `data class ShownLine(val text: String, val entryId: String, val isNew: Boolean)`
  - `data class ShownPerson(val id: String, val name: String, val lines: List<ShownLine>) { val hasNew: Boolean }`
  - `data class ShownGroup(val id: String, val name: String, val people: List<ShownPerson>)`
  - `fun visibleWhosWho(ww: WhosWho, progress: Map<String, EntryProgress>, seenAtMillis: Long?): List<ShownGroup>`.
    Groups keep data order, and people keep data order within their current group.
  - `suspend fun UserRepository.markWhosWhoSeen()`: sets `whosWhoSeenAt = time.millis()`.
  - `class WhosWhoViewModel(stories: StoryRepository, users: UserRepository, openOn: String?, saved: SavedStateHandle)`
    - `val ui: StateFlow<WhosWhoUi>`
    - `fun toggle(personId: String)`
  - `sealed interface WhosWhoUi`, with `Loading` and
    `Ready(groups: List<ShownGroup>, expanded: Set<String>, scrollTo: String?, sources: Map<String, String>)`.
    `sources` maps an entry id to its note, `"<author short>[ to <recipient short>] · <Dates.DAY>"`, for example
    "Lucy to Mina · 24 May".
  - Route `whos-who?open={open}`. `open` is an optional string, the entry's author id.

The view model's seen-at handling:
- It reads `whosWhoSeenAt` **once**, keeps it in `saved` under `"seenBefore"` (so rotation keeps it), and then calls
  `markWhosWhoSeen()`.
- `ui` always computes `isNew` against that snapshot, never against the live value.
- `openOn` is expanded and scrolled to only if `visibleWhosWho` contains that person.
- The expanded set lives in `saved`.

The screen:
- A `Scaffold` with a `TopAppBar` titled `Who's who` and the app's `BackButton`, then a `LazyColumn`.
- Each group name is a heading (`semantics { heading() }`).
- Each person is one clickable row with `Role.Button` and `stateDescription` "Expanded" / "Collapsed".
  - Folded, it shows the name (plus `new` if `hasNew`) and the last line.
  - Unfolded, it shows every line, each followed by its source note in a smaller muted style, and `new` after any
    new line.
- With no groups, it shows the empty text centred.
- `rememberLazyListState`, scrolled to `scrollTo`'s row on first composition.
