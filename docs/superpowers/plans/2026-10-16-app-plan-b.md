# App Plan B: Filters, Bookmarks List, Swipe — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A reader can filter the timeline by voice and document type, swipe between entries (following the filter or the whole story), and find, sort and remove bookmarks in their own list.

**Architecture:** All behaviour is pure Kotlin tested on the JVM: voices and the filter (`domain/Voice.kt`, `domain/EntryFilter.kt`), one reading order shared by the timeline and the reader (`domain/ReadingOrder.kt`), the bookmark list (`bookmarks/Bookmarks.kt`), skip to an entry (`domain/SkipAhead.kt`), and the saved state (`user/`). Compose screens and view models stay thin and are verified on the emulator with plan A's time travel and state seeding.

**Tech Stack:** as plan A (AGP 9.4.1, Kotlin 2.4.21, Compose BOM 2026.09.00, Navigation 2.10.2, Lifecycle 2.11.0, DataStore 1.2.1, kotlinx-serialization 1.11.0). `HorizontalPager` and `ModalBottomSheet` come from Compose Foundation and Material 3, already on the classpath. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-16-app-plan-b-design.md` (decisions B1–B10).

**Prerequisite:** plan A merged (main at `cf88054` or later). This plan names exact signatures and tests; unlike plan A it was not replayed into a scratch copy, so expected test counts are given per test class, not as suite totals.

## Global Constraints

- Package `com.jensen.draculanightbynight`; minSdk 26; compileSdk and targetSdk 37. Fully offline; no new permissions.
- Saved state: every new field has a default; plan A files load unchanged; an unknown voice or type name is dropped, an unknown sort falls back to `story` — never a crash.
- The filter changes the timeline list only (B3): Next card, end card, ahead banner, season card, arrivals and notifications use the whole story.
- Once read, always readable (plan A D3) holds everywhere: the reading order is built from `isReadable`.
- Every date is English (`content/Dates.kt`).
- Contrast: locked bookmark rows keep text at ≥ 4.5:1 (≥ 7:1 in high contrast); dimming is a lighter row background plus a lock icon, never faded text.
- Every icon button has a TalkBack label; touch targets ≥ 48 dp; chips and segmented buttons expose their selected state.
- Gradle needs the Android Studio JBR: run every Gradle command from `app/` as `JAVA_HOME="C:/Program Files/Android/Android Studio/jbr" ./gradlew …`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; PR bodies end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.

## Rulings made while writing this plan (flagged for the maintainer)

1. **Filter choices are stored as strings** (`filterVoices: Set<String>`, `filterTypes: Set<String>`) and read through `UserState.filter`, which drops unknown names. kotlinx-serialization's `coerceInputValues` does not drop unknown enum values inside a collection — the whole file would fail to load.
2. **Arrival times in locked bookmark rows use the Next card's format** (`Dates.WEEKDAY_TIME`, "Thursday 22 October, 23:00") rather than the spec's abbreviated "Thu 22 Oct", so the app has one way of saying when something arrives.
3. **The reader marks an entry read when its page settles**, so the view model no longer marks read on its own when the state first becomes Ready; the screen reports the settled page, including the first one.
4. **`ReaderState.previousId`/`nextId` are removed**; the pager's order replaces them (spec: `buildReader`'s own previous/next is replaced by `readingOrder`).
5. **The Bookmarks screen gets its own package `bookmarks/`**, like `welcome/` and `settings/`.
