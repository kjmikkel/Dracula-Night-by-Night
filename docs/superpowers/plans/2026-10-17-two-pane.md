# Two Panes on Wide Screens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On windows at least 600 × 480 dp, opening an entry shows it to the right of the timeline. A ✕ closes it, a ☰ hides the timeline, and phones keep today's behaviour.

**Architecture:** The `timeline` destination in `AppNavigation` becomes adaptive. When an entry is open and the window is wide, it shows `TwoPaneScreen`: the existing `TimelineScreen` and `ReaderScreen` side by side, with the reader's view model scoped to the timeline destination. Which entry is open lives in the timeline destination's `SavedStateHandle` as an `OpenEntry` request. The reader view model moves between entries with `open(request)`. A size change moves the open entry between the split and the `reader/{id}` route in either direction, so the back stack always matches the spec's rules.

**Tech Stack:** Kotlin, Jetpack Compose (BOM 2026.09.00), Navigation Compose 2.10.2, DataStore + kotlinx.serialization, Robolectric 4.16 + Compose UI tests (JVM, `testDebugUnitTest`).

**Spec:** `docs/superpowers/specs/2026-10-17-two-pane-design.md`

All paths below are relative to `app/app/` (the Gradle module). `M` = `src/main/java/com/jensen/draculanightbynight`, `T` = `src/test/java/com/jensen/draculanightbynight`. Run Gradle from `app/` (`./gradlew` there).

## Global Constraints

- Two panes only when the window is **≥ 600 dp wide and ≥ 480 dp tall**, measured in raw window dp (not size classes, not font-scaled).
- Timeline pane width: `TIMELINE_PANE_WIDTH = 360.dp` (starting value; meant to be tuned).
- The ✕ button: text `✕`, TalkBack label **"Close entry"**, at the start of the entry's top bar in place of `‹ Back`.
- The ☰ button: text `☰`, TalkBack label **"Show timeline"**, `Role.Switch`, on while the timeline is shown. This follows the Bookmark switch's pattern ("Bookmark, on/off").
- The "timeline hidden" choice is stored in `UserState` (DataStore), defaults to `false`, and survives rotation, folding and restart.
- A fresh app start always shows the full-width timeline. An open entry is restored only from saved instance state (rotation or process death), never on a fresh launch.
- No new accessibility-ratchet baseline entries, except copies of entries already baselined for `TimelineScreen` or `ReaderScreen`, with the same reason and issue link.
- Phones (either orientation) behave exactly as today. Every existing test passes unchanged, except call sites of changed constructors.

## Review Focus

1. **Two quick taps on different rows in the split view** should leave the second entry open, and one Back should close the pane. It should not stack two readers or pop the timeline. *Test: Task 7 `twoQuickTapsLeaveTheSecondEntryOpen`.*
2. **Process death with the pane open** should restore the split, on the entry the reader had swiped to, not the one first tapped. *Test: Task 7 `theSplitSurvivesStateRestorationOnTheSwipedToEntry`.*
3. **The open entry isn't in the filtered timeline** (reader following All): no row is highlighted and nothing crashes. *Test: Task 5 `rowItemIsNullForAnEntryTheListDoesNotShow`.*
4. **A window exactly 600 × 480 dp, or 1 dp under either**, behaves as the rule says (multi-window resizing lands on these). *Test: Task 2 `theBoundaryIsInclusive`.*
5. **Large text (font 2.0, Extra large) in a right pane narrower than a phone** passes the ratchet. *Test: Task 6 ratchet cases in the LARGE looks.*

**Interfaces:**
- Consumes: Tasks 2–5.
- Produces:

```kotlin
@Composable fun TwoPaneScreen(
    timeline: TimelineViewModel,
    reader: ReaderViewModel?,          // null: no entry open, the timeline fills the window as today
    timelineHidden: Boolean,
    onOpen: (id: String, filtered: Boolean) -> Unit,
    onClose: () -> Unit,
    onToggleTimeline: () -> Unit,
    onBookmarks: () -> Unit,
    onSettings: () -> Unit,
)
```
It's a `Row`. The timeline is always its first child, so it keeps its place when the reader appears or goes. It is shown unless `reader != null && timelineHidden`, and it's wrapped in `rememberSaveableStateHolder().SaveableStateProvider("timeline")` so its list position and opening anchor survive being hidden. The timeline is `TimelineScreen(…, selectedId = reader?.currentId)`. With a reader, it's `Modifier.width(TIMELINE_PANE_WIDTH)` followed by a `VerticalDivider`. Without one, it's `Modifier.weight(1f)`. Then, if `reader != null`, comes `ReaderScreen(reader, onBack = onClose, pane = PaneControls(!timelineHidden, onToggleTimeline, onClose))` with `Modifier.weight(1f)`, plus `BackHandler(onBack = onClose)`. Both screens need a `modifier` parameter for this, defaulting to `Modifier`. The name ends in `Screen`, so `CoverageTest` requires a case for it.

### Task 7: Wire the panes into navigation

**Files:**
- Modify: `M/MainActivity.kt` (`AppNavigation` becomes `internal`, and its destinations are listed below)
- Test: `T/TwoPaneNavigationTest.kt` (new, Robolectric, `createAndroidComposeRule<ComponentActivity>()`; it overrides `LocalWindowInfo` with a mutable size, as `TimelineRotationTest` does, and composes `AppNavigation(testApp(), MutableStateFlow(null), "timeline")` inside `InLook`)

**Interfaces:**
- Consumes: everything above.
- Produces: the behaviour below, and nothing new for other tasks.
  - `private const val OPEN_ENTRY = "openEntry"` is the timeline entry's `SavedStateHandle` key, holding `OpenEntry.encode()` or `null`.
  - `private fun NavController.openEntry(request: OpenEntry, wide: Boolean)`. If wide: set `getBackStackEntry("timeline").savedStateHandle[OPEN_ENTRY]` and `popBackStack("timeline", inclusive = false)`. Otherwise: `navigate(request.route()) { launchSingleTop = true }`. Every request gets a fresh `seq` (`SystemClock.elapsedRealtimeNanos()`).
  - The `reader/{id}?filtered={filtered}&all={all}` route has a new `all` Bool argument (default false), passed as `followingAll`.

Behaviour per destination (`val wide = windowIsWide()` is read once in `AppNavigation`):
- **timeline:** reads `OPEN_ENTRY` and always shows `TwoPaneScreen`. If wide and it's set, the reader is `viewModel(key = "pane-reader") { ReaderViewModel(…, request.id, request.filtered, createSavedStateHandle(), request.followingAll) }`, plus `LaunchedEffect(request) { reader.open(request) }`. Otherwise the reader is `null`. ✕ and Back clear `OPEN_ENTRY`. ☰ calls `app.users.setTimelineHidden(!hidden)` in `app.scope`. If narrow and it's set: `LaunchedEffect` navigates to the pane reader's `openEntry().route()` (via `viewModel(key = "pane-reader")`, which returns the live one) and clears `OPEN_ENTRY`. `onOpen` calls `nav.openEntry(OpenEntry(id, filtered), wide)` with the `isResumed` guard kept.
- **bookmarks:** `onOpen` calls `nav.openEntry(OpenEntry(id, filtered = false), wide)`.
- **reader:** `LaunchedEffect(wide) { if (wide) nav.openEntry(vm.openEntry(), wide = true) }`. The reader closes itself into the split, dropping anything between it and the timeline.
- **notification** (`openRequests`): `nav.openEntry(OpenEntry(id, filtered = false), wide)`, keeping today's `popUpTo("timeline")` for the narrow path.
