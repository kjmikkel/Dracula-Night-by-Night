# Dracula Night by Night — Sub-project 1: Story Dataset

**Status:** Draft for review · **Date:** 2026-10-14 · **Related:** [App design](2026-10-14-app-design.md)

## Purpose

Produce a structured, dated, reproducible dataset of every entry (diary, letter,
telegram, newspaper cutting, etc.) in Bram Stoker's *Dracula*, so the Android app
can unlock each entry at its in-story date and time. The dataset is the contract
between the text and the app; it is generated by a script committed to the repo
so contributors can fix errors via pull requests.

## Context

- The app is a free, open-source (Apache-2.0) Google Play release; the dataset
  ships inside it.
- Source text: Project Gutenberg eBook #345, HTML edition (`pg345-images.html`).
  The EPUB edition is the same XHTML split per chapter and is used only for
  cross-checking. The `.txt` edition is not used (it loses the italic datelines).
- *Dracula* is public domain. Project Gutenberg boilerplate is stripped and the
  "Project Gutenberg" name is not used in the shipped product, per their license.

## Success criteria

1. Every word of the novel's body text appears in exactly one entry (verified
   automatically).
2. Every entry has a type, author, date within 3 May – 6 Nov 1893, and a time
   (exact or marked estimated).
3. Entry ids are stable across pipeline re-runs; an id disappearing is reported.
4. Rebuilding from the same inputs yields a byte-identical `entries.json`.

## Entry schema

| Field | Type | Example | Source |
|---|---|---|---|
| `id` | string | `1893-05-03-jonathan_harker-01` | generated: date, author, per-day sequence |
| `chapter` | int | `1` | HTML `chapNN` anchor |
| `order` | int | `12` | position in the book (0-based, contiguous) |
| `type` | enum | `diary` | header + overrides |
| `author` | character id | `jonathan_harker` | header + overrides |
| `recipient` | character id \| null | `lucy_westenra` | header + overrides |
| `date` | ISO date | `1893-05-03` | italic dateline, or inherited |
| `time` | `HH:MM` | `20:35` | overrides (required by validation) |
| `timeEstimated` | bool | `true` | overrides |
| `place` | string \| null | `Bistritz` | dateline |
| `header` | string \| null | `Letter, Lucy Westenra to Mina Murray` | original header text |
| `headerNamesParties` | bool | `true` | `header` names both `author` and `recipient` (#177) |
| `body` | Block[] | see below | parsed markup |

`type` values: `diary`, `phonograph`, `letter`, `telegram`, `newspaper`, `memo`, `log`.

**Block**: `{ "role": "para" | "dateline" | "salutation" | "signoff" | "verse" | "note", "spans": [{ "text": string, "italic": bool }], "repeats"?: [start, end] }`.
`repeats`, only on an entry's first non-note block, is the `[start, end)` character range of its text that says
only the date (and place) the entry's fields already give, with what joins it on (`4 May.—`). The text is never
cut; the app may skip the range (#177).
Line breaks inside a block are represented as `\n` in span text.
HTML class mapping (initial): `r` → `dateline`/`signoff` (by position), `nind`
→ `salutation`, `poem`/`stanza` → `verse`, `c` notes such as "(Kept in
shorthand.)" → `note`.

**Characters** (`characters.json`): `[{ "id": "jonathan_harker", "name": "Jonathan Harker", "short": "Harker" }]`.
Every `author`/`recipient` must exist here. Non-person authors (e.g. a
newspaper such as `dailygraph`, a ship's captain, a firm of solicitors) are
also listed here so they work with the app's filter.

**Id generation** uses the *parsed* date and author, before overrides are
applied, so editorial corrections to date or author do not change an id.

### Decisions

- **Year is 1893.** Weekdays mentioned in the text match 1893. The app displays
  only day and month.
- **Ordering:** story order is `(date, time, order)`. `order` preserves book
  position as a tie-breaker and drives "read freely" mode ordering.
- **Splitting:** a new entry begins at each document header, each italic
  dateline, and each "Later" / "Same day" style marker. Dateless pieces inherit
  the preceding date. Each piece unlocks at its own time.

## Pipeline

Run with `python -m pipeline build` (Python 3.12, BeautifulSoup + PyYAML, pytest).

1. **Parse:** load HTML, verify checksum, strip Gutenberg header/footer, walk
   chapters into a flat stream of role-tagged blocks.
2. **Split:** segment the stream into entries per the splitting rule.
3. **Classify:** derive `type`, `author`, `recipient` from header text via a rule
   table (e.g. `Letter, X to Y`, `Telegram from X to Y`, `X's Diary/Journal`,
   `Cutting from ...`); unmatched headers are reported.
4. **Merge overrides:** apply `overrides.yaml`, keyed by entry id:
   ```yaml
   1893-05-03-jonathan_harker-01:
     time: "20:35"
     estimated: false
   1893-08-08-dailygraph-01:
     time: "07:00"
     estimated: true
     note: "Morning edition"
   ```
   Overrides may also set `type`, `author`, `recipient`, `place`, and force
   `split_after: <block index>` or `merge_with_next: true`.
   An override whose id matches no entry is a **build error**.
5. **Validate** (any failure fails the build):
   - required fields present; enums and character ids valid;
   - dates within 1893-05-03 .. 1893-11-06; every entry has a `time`;
   - ids unique; `order` contiguous;
   - **text conservation:** whitespace/punctuation-normalized concatenation
     of all entry bodies (plus headers) equals the normalized book body;
   - **id stability:** ids present in the previous committed `entries.json`
     but missing now are reported as warnings (errors with `--strict`).
6. **Emit:** pretty-printed, key-sorted `entries.json` and `characters.json`.

`python -m pipeline report` lists entries lacking a time (dateline + first
sentence) to drive the editorial pass. A first pass of estimated times is
proposed by Claude and reviewed by the maintainer; each estimate carries a
`note` explaining its reasoning where non-obvious.

The prebuilt Room database is **not** produced here; the app build converts
`entries.json` so the DB schema has a single owner.

## Testing

- Parser fixtures from tricky passages: chapter openings, letters with
  datelines and sign-offs, telegrams, the "Dailygraph" cutting, the ship's log,
  verse, multi-part diary days with "Later".
- Text conservation and validation run on the full book in CI.
- Override error cases: stale id, invalid character, invalid time.
- Determinism: two consecutive builds produce identical output.

## Out of scope

Translations, alternative editions, annotations or footnotes, audio.
